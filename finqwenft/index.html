第 01 关 · 概念地基
大模型到底是个啥（10 分钟极简版）
学完你就能：用自己的话向同事解释「大模型、预训练、微调、后训练」是什么关系。

1大模型 = 超级文字接龙机器

别被「人工智能」吓到。大模型的核心其实特别朴素：它是一台读过几乎整个互联网文字的「超级文字接龙机」。

打个比方你玩过成语接龙吧？给你「一心一…」，你脱口而出「意」。大模型干的是同一件事：给它一段前文，它猜「下一个字最可能是什么」。只不过它接龙接到极致——读了海量文字之后，这种「接下一个字」的能力，就表现成了理解、推理、写作。

2参数 = 大脑里的旋钮

你常听到「320 亿参数」。参数是什么？

打个比方参数就是模型大脑里一个个可调的小旋钮（其实就是一堆数字）。每个旋钮拧到什么位置，共同决定了它怎么接龙。「320 亿参数」= 320 亿个旋钮。所谓「训练」，就是不断微调这些旋钮，让它接龙越接越对。

3预训练 vs 微调 vs 后训练（一张图讲清）

这三个词最容易搞混。用「培养一名医生」作总类比，一次讲透：

预训练是「别人花大钱造好的通才」，微调是「我们花小钱教它一门专业课」。
  • 预训练 = 从小学读到医学院毕业：海量通识，成本天文数字，产出一个「什么都懂一点」的通才。这一步阿里已经替我们做完了——Qwen2.5 就是产物。
  • 后训练 = 毕业后一切进阶训练的总称（规培、专科、职业道德训练都算）。业内的 SFT、RLHF、DPO 都属于后训练。
  • 微调（我们做的 SFT，监督微调） = 后训练里最常用的一种：给它看「病例 + 标准诊断」的成对示例。我们的「病例」= 报销记录，「标准诊断」= 合规判定 JSON。
包含关系：预训练造出基座 → 后训练（微调是它的子集）→ 把通才变专才。

4为什么不从零训，而要「站在基座上」

打个比方想开一家面馆，你需要自己种小麦吗？不需要。从零预训练一个大模型，要几千张顶级 GPU 跑几个月；而站在基座上微调，4 张卡几小时就够。基座已经会中文、会读文本、会输出 JSON，我们只需要教它「费控合规」这一门专业课。

第 02 关 · 方法论核心 · 必修
决策课：这个任务到底该不该用微调 LLM
学完你就能：拿到任何一个新需求，自己判断「该微调 LLM，还是该用别的工具」。
为什么这关最重要「选错工具」是小白最大、最贵的坑，比任何训练报错都致命。训练报错顶多浪费你几个小时；工具选错，浪费的是几周甚至一个项目。所以这一关排在动手之前。

真实故事：本项目主人（Kenno）原本提了三个想法——汇率预测、用户收入预测、费控合规。只有一个适合微调 LLM。哪一个？为什么？看这张表：

任务本质用微调 LLM？正确工具
汇率预测数值时间序列✗ 不行ARIMA/GARCH、XGBoost、时序神经网络
用户收入预测结构化表格回归✗ 不行LightGBM / XGBoost
费控合规分析文本理解 + 软规则推理 + 结构化判断✓ 主场微调 LLM
  • 汇率预测：输入是数字序列、要输出精确数值。LLM 是「文字接龙机」，最不擅长精确算数——就像让语文老师去做高频交易。
  • 用户收入预测：结构化表格进、数字出。这是 LightGBM/XGBoost 的主场，又快又准又便宜。
  • 费控合规：文本进、要理解「软规则」、输出结构化结论 + 解释。这才是 LLM 的主场。

1全量微调的麻烦 → LoRA 的便签妙招

全量微调是把 320 亿个旋钮全部重调。

问题在哪这等于把整栋 100 层大楼重新装修——第一贵到跑不动（32B 全量微调连基座带优化器状态远超我们 192GB 显存），第二还容易把原本学会的通识「装修坏」（术语叫灾难性遗忘）。所以我们不重装，改贴便签。
LoRA = 便签纸改造法大楼一根钉子不动（基座参数冻结），只在每个房间门上贴一张薄薄的「修改便签」——上面写「这个房间的行为往合规分析方向偏移多少」。训练时只写便签，不动大楼。
这张「大楼 + 便签」是全书标志图。记住它，LoRA 就懂了一半。
  • 为什么便签就够？研究发现「专业化改造」需要的改动量本质很「薄」（术语：低秩）——不用重画整张 1000×1000 大表格，用一张 1000×16 和一张 16×1000 的窄条相乘就能近似。这个 16 就是 rank=16。
  • alpha=32 = 便签的「音量旋钮」，控制便签对大楼行为的影响力度（惯例设成 rank 的 2 倍）。
  • dropout=0.05 = 训练时随机盖住 5% 便签内容，防止死记硬背（防过拟合）。
  • target=all = 大楼每层每个房间都贴（所有线性层），比只贴部分更稳。
  • adapter 为什么这么小：产物只是「便签合集」，不是大楼本身。大小随基座和 rank 走——7B 约几十 MB，我们的 32B（rank=16、target=all）约 200~300 MB。看到几百 MB 别慌，这是正常的。这也是为什么第 09 关推理时必须「基座 + adapter」一起加载。

2量化 & QLoRA：把大楼压缩着用

量化 = 记账精度从「分」压到「元」模型参数本是高精度小数（16 比特记一个）。4-bit 量化 = 每个数只用 4 比特（16 个档位）来记，体积压到 1/4，代价是略微失真。
同一个数，压缩后略糊但省 3/4 空间——大楼只是「被参观」，糊一点无伤大雅。
QLoRA = 冻结大楼压成 4-bit + 便签仍用高精度训大楼只是「被参观」（前向计算），压缩一点没关系；便签是「正在写的作业」，必须高精度。结果：32B 原本 bf16 加载要 ~64GB，4-bit 只要 ~18GB，我们 4×48GB 的卡变得非常宽裕。

先决条件（0 基础必读，否则第一条命令就报错）

① 4×L20 的 GPU 服务器从哪来？三条路：公司/学校有机房 → 找运维要一台；没有 → 云上按小时租（国内 AutoDL、阿里云 PAI、腾讯 GPU；海外 AWS/Lambda），搜「4 卡 48G 显存」实例。本机的普通笔记本跑不了 32B，别在自己电脑上试。

② 什么是「终端」、怎么连上服务器？「终端」就是一个黑底白字、只能打字的窗口——你在自己电脑上打开它，用 SSH（一种远程登录方式）连进服务器，之后你敲的每条命令都在服务器上跑。连接命令长这样（把 用户名 和 服务器IP 换成运维/云平台给你的）：

在你自己电脑的终端里

玩具数据的超参真相（兑现第 03 关 epoch 伏笔）

原始 yaml 的等效 batch=64（2×8×4），是为真实的几百~几千条数据准备的。但我们只有 10 条训练数据——64 比 10 还大，意味着每个 epoch 都凑不满一次参数更新，训练几乎在空转。这不是 bug，是玩具数据的又一个局限。

想让 12 条认真跑起来把 yaml 改成：gradient_accumulation_steps: 1（有效 batch 降到 2×1×4=8，凑得满更新）、warmup_ratio: 0（总步数才几十步，热车没意义）、num_train_epochs: 5~10（反正是背题实验，敢多跑几遍）。但记住：这只是让流程「转起来」，真正的解药永远是扩数据（第 11 关）。

如果显存爆了（OOM）

看到 CUDA out of memory 时，按顺序改 yaml
gradient_checkpointing: true # ① 先确认它是 true（省显存主开关）最先查这个
per_device_train_batch_size: 1 # ② 从 2 降到 1，每卡少看点再降这个
cutoff_len: 2048 # ③ 从 4096 降一半，序列短更省显存还爆就降这个
别踩这个坑OOM 时不要靠把 gradient_accumulation_steps 往上堆——那治不了单步显存爆，还会在小数据上把有效 batch 撑得更大、更空转。省显存要靠上面三招（尤其 checkpointing 和 cutoff_len）。

第 09 关 · 动手实操 · 步骤 4 · 全书最重要的纪律
评估与基线对比
学完你就能：用数字回答「微调到底有没有用」，并永远记住基线对比这条铁律。
基线是什么基线（baseline）= 不微调的原版 Qwen2.5-32B，用一模一样的 prompt 去做同一套考题的成绩。就像新药必须和安慰剂对照才知道有没有效——只说「吃了药病好了」毫无意义，也许不吃也会好。
!
红线 · 第 3 次出现 · 全书最粗一条 微调模型没赢过基线 = 这次微调白做。小白最常见的自欺：训完随手聊两句，「感觉不错」就宣布成功。感觉不算数，数字才算数。
!
最致命的陷阱 · 一定要看懂这段 直接 python evaluate_feikong.py 会打印出全是 1.0 的满分——但那是假的！脚本里那行 preds = [json.dumps(g…) for g in golds] 是「假装模型完美复现答案」的占位演示（demo），它拿标准答案当模型输出，当然 100% 对。它根本没调用你的模型。被这个假满分骗着交差，是全手册最容易犯的错。

拿到「真分数」的正确三步

evaluate 脚本本身没错，它是个合格的「阅卷器」；缺的是喂给它真实的模型输出。正确流程是：

  1. 让「微调后模型」真的答一遍 val 集——对 feikong_val.jsonl 里每条的 user 输入做推理，收集它真实生成的文本，这才是真 preds。
  2. 让「未微调基线」答同一套题——同样的输入、同样的 prompt，只是不挂 adapter，得到基线 preds。
  3. 两组 preds 分别喂进 evaluate() 函数对比——微调的四项指标必须高过基线，才算真赢。

用 LLaMA-Factory 自带的批量预测模式生成真实输出最省事（不用自己写推理循环）：

终端 · 用 predict 模式生成真实 preds
# 复制一份 yaml 改成预测模式：do_train:false + do_predict:true + predict_with_generate:true
# eval_dataset 仍指向 feikong_val，adapter 指向你第 08 关的输出目录，再运行：
llamafactory-cli train qwen32b_predict.yaml微调模型答卷
# 完成后 output_dir 里会出现 generated_predictions.jsonl —— 这才是模型真实输出
# 把它的 predict 字段读成 preds、label 字段读成 golds，喂进 evaluate_feikong.py 的 evaluate()
# 再对「不挂 adapter 的基线」重跑一遍上面全过程，两组分数对比 ← 这才是基线对比
诚实提醒 · 这是全流程最难的一步「让模型真的答一遍卷再阅卷」比前面所有步骤都更需要动手，卡在这里非常正常。别用假满分蒙混——宁可在这一步多花时间，也不要拿着 demo 的 1.0 去汇报。

怎么读结果（诚实版）

这是空模板——真正的数字要你跑完 evaluate 亲手填。这个「填数字」的仪式，就是在强化基线对比的纪律。
  • 微调 > 基线：链路和方法都对，接下来加数据放大优势。
  • 微调 ≈ 或 < 基线：在 12 条玩具数据下这是大概率结局，不代表你失败——它证明的是「数据不够时微调无法起效」，这正是本课要你带走的最重要结论。解法在第 11 关：扩数据。

第 11 关 · 进阶 · 后训练工程
从玩具到生产：真正的后训练工程
学完你就能：说出这个项目走向真实上线的四步路线图。

跑通玩具版之后，真正让模型能上线，还有四步。每步讲清「做什么 + 为什么」：

① 扩数据（重中之重）

12 条 → 数百~数千条。来源 = 真实脱敏报销单 + 公司费控制度文本。

加速技巧：蒸馏 + 人审用最强的商用大模型按规则批量生成「判定初稿」，人工逐条校对后才能入库。就像请特级教师写习题初稿，教研组审核后才发给学生。
!
红线 · 第 3 次（说到做到，这是第三遍）数据质量 = 微调成败。这一步做扎实，前面所有关卡才有意义。

② 规则对齐

把「命中规则」的取值固定成一份规则字典（封闭枚举表），标注、训练、评估三方用同一套编号。

为什么否则同一个问题今天叫「异地报销」明天叫「城市不符」，模型学不稳、F1 也没法算。就像全公司统一会计科目表。

③ 接入系统

用 vLLM（高性能推理引擎）挂载「基座 + LoRA adapter」对外提供 API，接进报销审批流。

定位是「自动初筛 + 风险标记 + 人工复核」，不是替代人——高风险单子标红给人看，AI 当助手不当法官。

④ 数据飞轮

人工复核纠正的结果回流成新训练数据，定期重训。模型越用越准，形成闭环。
